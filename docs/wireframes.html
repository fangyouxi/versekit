06

CLI · 同一内核的另一张脸

默认 JSON（给 agent/脚本），--human 才给人看。能力集合必须与 Web 等价。

# agent / 脚本路径 $ vk account list --json { "accounts": [ { "platform": "douyin", "state": "expiring", "expires_in_h": 71 }, { "platform": "xiaohongshu", "state": "expired", "last_ok": "2026-10-24T09:12Z" } ] } $ vk publish ./ep12.mp4 --to douyin,xhs,bili,youtube \ --schedule 20:00 --json { "publishes": ["p_1a","p_1b","p_1c","p_1d"], "mode": "auto" } # 失败自动降级为 notify
# 人的路径 $ vk now --human 账号 抖音 ● 警告 71h 后失效 小红书 ● 失效 3 天未采集 → vk account reauth xhs tiktok auto 已发 · 仅自己可见 → 等你放行 队列 发布 1 · 采集 38 · 失败 0 通道 飞书 已连接（2 分钟前投递成功） $ vk publish ./ep12.mp4 --to all --dry-run --human 将发布 4 个平台（mode=auto）： douyin auto 定时 20:00 xiaohongshu auto 定时 20:00 ⚠ 自动化通道，可能降级 bili auto 定时 20:00 youtube auto 定时 20:00 tiktok 跳过 （App 审核中，暂只能 SELF_ONLY）

设计要点：--dry-run 与 --json 是产品能力不是调试开关——agent 需要"先演一遍再执行"。

07

三端关系（一页看懂）

同一命令，三种呈现；业务逻辑只有一份。

用户意图CLIWeb飞书 / Telegram
看号是否健康vk account list账号墙失效卡片（被动）
重新登录vk account reauth扫码页「查看怎么修」→ 深链
发一条内容vk publish发布台“已发布”结果卡片
重试失败vk publish retry失败列表卡片按钮「重试」
看数据vk stats --json看板 / 作品详情每日摘要卡片
审批vk approval ok|no待审列表卡片「发布 / 打回」

三端都由 core/commands.ts 的注册表派生，CI 校验三者命令集合一致（PRD §5.4）。
